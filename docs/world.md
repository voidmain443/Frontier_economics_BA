# 하나의 세계 (2026-10-30 2차 grill)

`docs/redesign.md`의 3단계까지 끝난 사이트에서 접힌 공간은 청사진 빈 공간이다. 그 안에 휘어진 페이지 한 장만 떠 있다. 2차 grill(질문 세 차례)에서 그 공간을 3부의 아카이브 건물 하나로 정했다. 이 문서는 `redesign.md` 다음 단계의 기준이다. `redesign.md`의 원칙 가운데 바뀐 것은 '접힌 상태의 표현' 하나이며, 아래 표에 적었다.

## 고정된 답

| 질문 | 답 |
|---|---|
| 공간 | **하나의 세계.** 1·2·3부는 아카이브 건물이라는 한 공간의 장소다. 건물은 3부 그림 3.1의 평면도 그대로다. 아래에서부터 방법, 제도, 시장, 주체의 네 층이 있고, 층마다 방이 여섯 개, 모두 24개다. |
| 페이지와 건물 | **페이지는 건물을 지나는 길이다.** 1부의 리본은 단계 순서대로 방을 지나간다. 읽는 줄에 온 그림은 리본이 지금 지나는 방에서 솟는다. 따라서 '제자리'와 '자기 방'이 같은 자리다. 3부 본문의 "과목은 이 건물을 지나는 한 길이다"를 공간으로 만든 것이다. |
| 두 방에 걸친 그림 | **두 방의 경계에서 솟는다.** 같은 층이면 두 방 사이의 벽에, 다른 층이면 두 층 사이의 바닥판에 둔다. 예를 들어 IS–LM은 재화 시장과 화폐 시장 사이의 벽에서 솟는다. |
| 2부 | **방이 군중으로 찬다.** 1부의 방에는 대표 주체가 하나 있다. 2부에서는 같은 방이 사람 80명, 기업 400개, 은행 10개로 찬다. 대표 주체라는 가정을 푸는 일이 그대로 공간에 나타난다. |
| 3부의 절정 | **건물 전체와 길들.** 스크롤을 따라 카메라가 물러나면 건물 전체가 처음으로 보인다. 1부가 지나온 고전의 길과 3부 4절의 세 길(질문, 주체, 시장)이 건물을 지나는 선으로 그려진다. 방 이름은 과목으로 가는 문이다. |
| 3D 모드 | **접힘 하나(D62 유지).** 접힌 상태에서는 드래그로 시점을 돌릴 수 있다. 다시 스크롤하면 카메라가 읽는 자리로 돌아온다. 같은 조작을 키보드로도 할 수 있다. 버튼, 패널, 다이브는 여전히 없다. |
| 영상에서 가져올 것 | 종이의 두께와 압출된 단계 제목, 여백 콜아웃과 지시선, 눈금자, 도면 요소(치수선, 와이어프레임, 수식), 접힌 채로 하는 그림 조작. 도면 요소는 지금 읽는 그림과 연결된 것만 그린다. |
| 순서 | **병행.** 전공자 확인(`docs/phase4-test.md`)을 지금 빌드로 준비하는 동안 세계 시제품을 만든다. 확인 세션 끝에 시제품을 함께 보여 준다. |
| 첫 결과물 | **1부 1~3단계 시제품.** 건물 전체의 뼈대를 세우고, 리본이 한 시장 → 가계 → 기업의 방을 지나는 구간을 완성한다. |
| 주체 모형 | **시안 두세 개를 렌더해 고른다.** 지금의 흰 석고 모형을 포함한다. 2부의 군중용 단순형도 같은 스타일로 만든다. |
| 성능 | **노트북 내장 GPU에서 초당 60프레임.** Apple M 시리즈 기본형급 GPU의 Chrome이 기준이다. |

## 지키는 선

1차 grill에서 걷어 낸 것으로 돌아가지 않기 위한 조건이다.

- 그림과 방을 잇는 실(선)은 없다. 리본이 그 방을 지나가므로 실이 필요 없다.
- 건물은 도면의 선과 반투명한 바닥판으로 그린다. 불투명한 벽으로 읽는 줄을 가리지 않는다. 읽는 자리 가까이의 벽은 투명해진다.
- 떠다니는 카드, 탑, 선반, 무대는 없다. 공간에 서는 것은 방, 그림의 숨은 축, 주체 모형, 2부의 군중뿐이다.
- 카메라의 움직임은 모두 스크롤 위치의 함수다. 예외는 드래그로 돌린 시점 하나이며, 이것도 스크롤하면 원래대로 돌아온다. 자동으로 재생되는 카메라 이동은 없다.
- 동작 줄이기(prefers-reduced-motion)를 켜면 방 사이 이동은 짧은 페이드로 바뀐다.

## 배치표 초안

그림마다 방 하나, 또는 두 방의 경계를 정한다. 이 표는 원고처럼 사용자 검토를 받은 뒤에 확정한다(W0). 방 이름은 `p3-figs.js`의 LAYERS와 같다. 층 번호는 방법 0, 제도 1, 시장 2, 주체 3이다.

### 3부의 길

3부 4절의 세 길은 링크에서 자동으로 방 순서를 얻는다. 링크가 가리키는 그림이나 절의 방을 위 두 표에서 찾는다. 손으로 그린 선은 없다. 고전의 길은 1부 표의 순서 그대로다.

| 길 | 링크 순서 | 방 순서 |
|---|---|---|
| 질문: 왜 어떤 나라는 부유한가 | 5단계, 6.1, 8.10, 8.11, 2부 3절 | Equilibrium → Capital → Property → History → Firms |
| 주체: 가계 | 2.1, 2.2, 2.3, 6.2, 8.4, 8.9, 2부 4절 | Households → Households ∣ Goods → Households ∣ Capital → Goods ∣ Money → Capital → Households → Strategy |
| 시장: 노동 | 3.1, 6.3, 8.7, 7.2, 2부 1절 | Firms → Labor → Labor ∣ Regulation → Measurement ∣ Goods → Goods |

## 구조와 구현

### 세계의 좌표

- 방 하나는 가로·세로 2.4, 층 높이는 1.4 단위에서 시작한다. 페이지 폭(900px)이 1 단위이므로 방 안에 리본과 솟은 구조가 들어간다. 값은 W1에서 화면을 보고 정한다.
- 리본의 모양은 지금과 같다. 읽는 줄에서 휘고, 읽은 부분은 뒤로 말려 올라간다. 움직이는 것은 건물이다. 그림마다 읽는 줄에 왔을 때 그 그림의 방(또는 경계)이 읽는 자리를 둘러싸도록 건물의 위치를 정한다. 그림과 그림 사이에서는 두 위치를 스크롤에 따라 부드럽게 보간한다. 층이 바뀌는 구간에서는 건물이 위아래로 움직이므로 독자에게는 페이지가 층을 오르내리는 것으로 보인다.
- 리본이 방의 벽을 지나는 자리에는 문이 뚫려 있다. 벽은 선으로만 그리므로 리본과 겹쳐도 읽기를 방해하지 않는다.

### 모듈

| 모듈 | 맡은 일 |
|---|---|
| `world.js` (새 모듈) | 건물(층, 방, 벽, 문, 바닥판), 배치표, 길 계산, 스크롤 위치에서 건물의 위치를 계산 |
| `p3-figs.js` | LAYERS를 건물과 평면도가 함께 쓰는 한 곳의 정의로 둔다. |
| `fold.js` | 건물 그리기(선은 `G.lines`, 바닥판은 `G.mesh`), 시점 돌리기, 콜아웃, 눈금자 |
| `gpu.js`, `shaders.js` | 종이 두께와 압출 제목을 위한 패스. 정리 때 지운 SLAB·CARD 셰이더(커밋 `877faf8`)에서 다시 시작할 수 있다. |
| `maquettes.js` | 고른 스타일의 주체 모형과 군중용 단순형 |

### 영상 요소의 뜻

구조 장치는 정보를 담을 때만 쓴다.

| 요소 | 담는 정보 |
|---|---|
| 종이 두께 | 페이지가 공간 속의 물건이라는 것. 두께는 일정하다. |
| 압출된 단계 제목 | 단계가 시작되는 자리. 리본이 새 방에 들어가는 자리와 같다. |
| 여백 콜아웃 | 지금 그림의 번호와 'Held fixed' 줄. 지시선은 솟은 축을 가리킨다. |
| 눈금자 | 1부 40분 중 지금 위치(분)와 단계 경계. 영상의 픽셀 좌표 대신 읽기 시간을 쓴다. |
| 치수선 | 솟은 축의 이름과 범위(예: 공장 규모 K = 1…5). |
| 와이어프레임 | 지금 지나는 방의 벽과 문만 그린다. |
| 떠 있는 수식 | 지금 그림의 식만 쓴다. 이미 `eqs`로 있는 식을 공간에 둔다. |
| 접힌 채로 조작 | 2부의 슬라이더를 움직이면 그 그림의 타일만 다시 캡처하고 그 그림의 구조만 다시 짓는다. |

### 시점 돌리기

- 접힌 상태에서 캔버스를 드래그하면 카메라가 읽는 자리를 중심으로 돈다. 좌우 ±60°, 위아래 −10°…+50°에서 시작한다.
- 휠이나 스크롤이 들어오면 돌린 각도가 약 0.6초에 걸쳐 0으로 돌아간다. 돌아오는 동안에도 읽는 자리는 바뀌지 않는다.
- 키보드: Alt와 화살표로 돌린다. 화살표만 누르면 지금처럼 페이지가 스크롤된다. Esc는 지금처럼 접힘을 푼다. Alt와 화살표가 브라우저나 운영체제의 단축키와 겹치는지는 W1에서 확인한다.

### 성능 예산

| 항목 | 예산 |
|---|---|
| 프레임 | 접힌 상태 16.7ms 이하(Apple M 기본형 Chrome, 1440×900, devicePixelRatio 2) |
| 드로 콜 | 프레임당 300 이하. 건물 선은 층마다 한 묶음으로 그린다. |
| 그림자 | 지금 방의 주체 모형과 군중만 그림자 지도에 넣는다. |
| 군중 | 인스턴싱. 한 방에 400개까지. 군중용 단순형은 모형당 삼각형 2,000개 이하로 한다. |
| 라벨 | 화면에 보이는 DOM 라벨은 80개 이하. 보이지 않는 방의 라벨은 만들지 않는다. |

| **W2. 1부 전체** | 4~8단계를 확정된 배치표대로 잇는다. 층을 건너뛰는 구간의 이동을 다듬는다. 고른 스타일로 주체 모형 7종을 다시 만든다. | 1부 30개 그림이 모두 자기 방이나 경계에서 솟는다. 60fps를 유지한다. |
| **W3. 2부** | 방이 군중으로 찬다. 슬라이더를 접은 채로 조작한다. | 2부 다섯 절이 모두 접힌 채로 동작한다. 군중 400개에서 60fps를 유지한다. |
| **W4. 3부 절정** | 건물 전체, 고전의 길과 세 길, 문. 3부의 문을 키보드로도 고를 수 있게 한다. | 길 네 개가 배치표에서 자동으로 그려진다. 문 24개가 모두 마우스와 키보드로 열린다. |
| **W5. 마무리와 재확인** | 화면 비율별 점검, 동작 줄이기, 성능 재측정. 새 참가자로 확인을 다시 한다. | `phase4-test.md`의 판정 기준을 다시 통과한다. 확인에 더할 질문의 기준도 통과한다. |

## 확인에 더할 질문

세계가 학습 목표에 기여하는지는 "누구의 결정인가"와 같은 질문으로 확인한다. 방은 주체, 시장, 제도, 방법을 공간으로 나눈 것이기 때문이다.

> 1. 그림 2.1은 건물의 어느 방에서 솟았습니까? 그 방은 무엇을 뜻합니까?
> 2. 1단계에서 3단계로 오는 동안 페이지는 어느 층에서 어느 층으로 움직였습니까? 왜 그렇게 움직였다고 생각하십니까?
> 3. 그림 3.2는 두 방의 경계에서 솟았습니다. 어느 두 방이며, 이 그림이 두 방에 걸친 이유는 무엇입니까?

판정: 세 질문 중 두 개 이상에 배치표와 맞게 답한 참가자가 과반이면 세계를 W2 이후로 넓힌다. 그렇지 않으면 방 표시(이름, 층의 구분)를 먼저 고친다. 그래도 답하지 못하면 '하나의 세계'를 '배경의 건물'로 줄이는 것을 검토한다.

## 위험

| 위험 | 대응 |
|---|---|
| 건물이 움직이는 동안 글이 읽히지 않는다. | 읽는 자리 주변의 화면 위치는 고정하고 건물만 움직인다. 이동은 그림과 그림 사이 구간에서만 일어난다. 읽는 줄의 그림이 솟아 있는 동안에는 건물이 멈춘다. |
| 층을 건너뛰는 이동이 어지럽다. | 이동 거리에 비례해 이동 구간을 길게 잡는다. 동작 줄이기에서는 페이드로 바꾼다. |
| 건물이 장식으로 읽힌다. | 확인에 더할 질문으로 측정한다. 실패하면 위 판정에 따라 줄인다. |
| 군중과 그림자로 60fps를 넘긴다. | 지금 방만 그림자에 넣는다. 군중은 인스턴싱과 단순형으로 그린다. 그래도 넘기면 군중을 점으로 대신한다. |
| HTML-in-Canvas API가 바뀐다. | 기능 감지(`htmlInCanvasSupport`)와 메서드 이름 두 가지를 모두 지원하는 지금 방식을 유지한다. |
